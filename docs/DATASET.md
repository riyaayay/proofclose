# Dataset

## Overview

The ProofClose evaluation cohort consists of 120 synthetic settlement rows forming 40 three-row settlement groups.

## Generation

Generated by `scripts/generate-fixture.ts` using deterministic seed `20260904` (a Mulberry32-family PRNG).
Re-running the generator from the committed source always produces byte-identical CSV files.

```bash
npm run generate:data
```

The generator outputs a SHA-256 of the concatenated settlement + ledger + bank CSVs to stdout.

## Cohort composition

| Scenario | Count | Expected decision |
|---|---|---|
| Fully evidenced and closeable | 97 | `CLOSED` |
| Financially closeable, bank narration unprovable | 3 | `EXCEPTION` (conservative abstention) |
| Missing merchant ledger record | 4 | `EXCEPTION` |
| Amount delta (ledger off by 100 paise) | 4 | `EXCEPTION` |
| Duplicate ledger candidates | 3 | `EXCEPTION` |
| Missing bank credit | 3 | `EXCEPTION` |
| Ambiguous same-value bank credits | 3 | `EXCEPTION` |
| Unknown adjustment | 3 | `EXCEPTION` |
| **Total** | **120** | **97 closed, 23 exceptions** |

## Independent entity-type sampling

Entity types (`payment`, `refund`, `transfer`, `adjustment`) and exception scenarios are sampled independently across the cohort:
- Entity type is drawn via realistic weighted proportions (~55% payment, ~20% refund, ~15% transfer, ~10% adjustment).
- Exception scenarios are independently distributed across entity types, rather than being confounded with a single entity type.
- The single semantic constraint is that `UNKNOWN_ADJUSTMENT` requires an `adjustment` entity (as ledger adjustment reasons apply strictly to adjustment rows).
- All other exception scenarios (`MISSING_LEDGER_RECORD`, `AMOUNT_DELTA`, `DUPLICATE_LEDGER_CANDIDATE`, `MISSING_BANK_CREDIT`, `AMBIGUOUS_BANK_CREDIT`, `UNVERIFIED_BANK_NARRATION`) span across multiple entity types.

## Key settlement groups

- **`setl_38`** — narration is `"CREDIT INWARD - BATCH REFERENCE LOST"` → produces 3 conservative abstentions (`UNVERIFIED_BANK_NARRATION`).
- **`setl_39`** — no bank credit row → produces 3 `MISSING_BANK_CREDIT` exceptions.
- **`setl_40`** — two bank credit rows with the same control total → produces 3 `AMBIGUOUS_BANK_CREDIT` exceptions (deliberate safety guard).

## Important notes

- All amounts are integer paise. No floating-point INR anywhere in the engine.
- This is a **synthetic** evaluation cohort. Do not use these metrics to claim production accuracy.
- The three conservative abstentions are financially closeable — the engine sacrifices throughput for proof correctness.
