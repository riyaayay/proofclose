# Metrics

## Evaluation cohort

120 synthetic records, seed 20260904, generated by `scripts/generate-fixture.ts`.
Run `npm run evaluate` to reproduce — the script writes `docs/metrics.json` and exits non-zero if numbers drift.

---

## Two truth axes — why closeRecall ≠ closeabilityRecall

The truth label file (`data/truth/expected_outcomes.csv`) has two separate columns:

| Column | Meaning |
|---|---|
| `financialTruth` | Whether the record *could* be closed in the data-generating world (`CLOSEABLE` / `HARD_EXCEPTION`) |
| `expectedControllerDecision` | What the controller *must* output, given its proof policy (`CLOSED` / `EXCEPTION`) |

These differ for the three **UNVERIFIED_BANK_NARRATION** rows:
- `financialTruth = CLOSEABLE` — the bank credit exists and the amount matches
- `expectedControllerDecision = EXCEPTION` — the bank narration does not contain `RAZORPAY` or `RZP`, so source cannot be proven; the engine correctly abstains

This is a deliberate, disclosed safety trade-off — not an error. It produces two separate recall numbers, both reported and labelled:

| Recall metric | Denominator | What it measures |
|---|---|---|
| **Close Recall (strict)** | `expected_closed` rows | Did the engine close every row it was supposed to? |
| **Closeability Recall** | `financial_closeable` rows | Did the engine close every row that *could* have been closed, including those it chose to abstain on? |

## Metric formulas

All values are computed live by `evaluate.ts` from the run output — nothing is hardcoded.

| Metric | Formula |
|---|---|
| Auto-Close Match Rate | `correct_closed / total` |
| Close Precision | `correct_closed / predicted_closed` |
| Close Recall (strict) | `correct_closed / expected_closed` |
| Closeability Recall | `correct_closed / financial_closeable` |
| Exception Precision | `correct_hard_exceptions / predicted_exceptions` |
| Hard-Exception Recall | `correct_hard_exceptions / hard_exceptions` |
| Financial-State Accuracy | `(correct_closed + correct_hard_exceptions) / total` |
| Conservative Abstentions | count of `engine=EXCEPTION ∧ financialTruth=CLOSEABLE` |
| **False Closures** | `predicted_closed − correct_closed` — **must be 0** |

## Confusion matrix (controller decision vs. expected decision)

|  | Engine: CLOSED | Engine: EXCEPTION |
|---|---|---|
| **Expected: CLOSED** | correctClosed | missed closures (would indicate a bug) |
| **Expected: EXCEPTION** | **falseClosures (critical — must be 0)** | predictedExceptions − falseClosures |

|  | Engine: CLOSED | Engine: EXCEPTION |
|---|---|---|

## Metric drift guard

`scripts/evaluate.ts` throws and exits 1 if any of these deviate for seed 20260904:
- `total = 120`
- `correctClosed = 97`
- `conservativeAbstentions = 3`
- `falseClosures = 0`
- `closeRecall = 1` (100% strict recall)
- `closePrecision = 1` (100% precision)
- `hardExceptionRecall = 1` (100%)

`npm run evaluate` is a required step before every submission or demo.
